How to use the API well — lessons baked into AMLClaw

hops = 1

For continuous TX monitoring, set hops = 1. You only need to know whether the counterparty (from / to) address itself carries a high-risk label — Sanctions, Freeze and the like. One hop skips the deep graph walk, so each cycle returns in a fraction of the time — exactly what high-frequency monitoring needs.

custom ruleset

Don't leave ruleset_id at the broad default. Point each monitor at your own ruleset — pick the categories and thresholds that match your business — and alerts get far more precise, with fewer false positives.

deep KYA on demand

Reserve multi-hop (3–5) for one-off deposit / withdrawal screening, where you genuinely need to trace source of funds. Keep deep hops out of the monitoring loop — depth there just costs latency.

rolling window · serial

Each cycle screens only [last run → now], never from zero — faster, no re-scanning. Run jobs one after another to respect API concurrency limits, and log every tx so you can prove full coverage.
