01这是什么 · 和 Width / DAIA 什么关系

先把「引擎」和「应用」这层关系讲清楚，客户最容易在这里绕晕。

底层引擎

Width · DAIA

链上情报与风控引擎：覆盖 11 条链的地址/交易筛查、自建制裁数据库、百万级标签地址、最深 5 跳资金追溯。这是「数据和能力」的来源。

对外 API

KYA / KYT API（V3）

把引擎能力开放成一套 REST API：KYA 查地址、KYT 查交易。客户拿一把 Key 就能调。

上层应用（我们卖的）

AMLClaw

把 API 封装成开箱即用的业务界面——筛查、监控、台账、证据报告。客户不用自己写代码，装上就能用。

类比帮客户理解：DAIA 是「发动机」，KYA/KYT API 是「油管接口」，AMLClaw 就是整台可以直接开走的车。客户既可以只接 API 自己造车，也可以直接用我们这台开源的车。

02客户为什么需要它

卖的不是功能，是「不出事」。先戳痛点，再给方案。

客户的三大痛点

  • 监管压力：MAS、FATF Travel Rule、各地牌照都要求对加密资金做 AML/KYT，做不到就拿不到 / 保不住牌照。
  • 脏钱风险：一旦收了制裁地址、混币器、黑客赃款的钱，账户可能被冻结、被追责，声誉和资金双输。
  • 说不清：出事时监管问「你当时怎么判断这笔干净？」，客户拿不出证据链，等于裸奔。

AMLClaw 怎么对症

  • 痛点一 → 事前筛查：入金/出金前先查地址和交易，脏钱挡在门外。
  • 痛点二 → 事中监控：地址收钱后持续盯，脏钱流入立刻告警，不是查一次就完。
  • 痛点三 → 可解释证据：每次命中都返回触发的具体规则 + 资金路径图，即拿即用的审计依据。

03四大功能 · 怎么讲怎么演

每个功能记住：一句话定位 → 解决什么 → 演示看点。

KYA

地址筛查

定位：查「这个地址干不干净」。粘一个 ETH 或 Tron 地址（自动识别链），做 0–5 跳的自身命中 + 间接敞口筛查——制裁、恐怖融资、混币器、黑客、暗网等。

解决：开户、上币、大额入金前的尽调（KYC/CDD）。

演示看点：风险等级（低/中/高/严重）+ 命中的具体规则 + 可交互的资金流向图。
KYT

交易筛查

定位：查「这一笔交易的钱脏不脏」。粘一笔交易哈希，选方向——in 查资金来源、out 查去向、或两者都查，入金出金用不同的规则。

解决：每一笔充值/提现的实时放行判断。

演示看点：与 Chainalysis 对齐的处置建议（拦截/复核/告警/监控）+ 逐笔路径证据。
地址监控

盯住一个地址的未来交易

定位：添加一个地址，自动盯它后续每一笔稳定币转账（ETH: USDT+USDC，Tron: USDT），按计划（每小时~每天）对每笔新交易自动 KYT——收款算 in、付款算 out。

解决：「查一次干净不代表永远干净」，持续风控。

演示看点：全量交易入台账（像区块浏览器），可只看有问题的，还能出「某时段共 X 笔、其中 Y 笔严重」的统计——证明我们把每一笔都检测了。
TX 监控

盯住一个对手方

定位：从任意 KYT 结果里，把这笔交易的 from 或 to 地址加入监控，周期性 KYA 复筛它本身的标签变化。

解决：今天干净的对手方，明天可能被打上制裁/冻结标签——第一时间知道。

演示看点：一旦对手方涉及 Sanctions（制裁）/ Freeze（冻结） 或风险等级升级，立即告警。

讲功能的节奏：KYA/KYT 是「进门安检」（事前一次性查），两个监控是「巡逻队」（事中持续查）。客户几乎都会问「查完之后怎么办」——答案就是两个监控。

04核心卖点 · 我们凭什么赢

这些是打单时反复强调的差异化。

🗄 服务端规则

规则集在服务端维护，客户本地不用养规则库。用内置默认，也能自定义 ruleset，按业务挑类别和阈值。

🔎 完整路径证据

每次命中都给出触发的规则和资金流向图，天然是给监管看的审计链。

⚡ 监控又快又省

持续监控用 hops=1、滚动窗口只筛增量、串行调用——速度快、API 调用省。

🔓 开源可私有部署

MIT 开源、无数据库，数据不出客户服务器，一把 Key、Docker 一键起，随处部署。

🌐 自建数据 · 11 链

自建制裁数据库（OFAC/UN/EU/UK）、百万级标签、11 条链近实时，秒级检索。

💸 大客户免费

Width 对钱包/托管/支付/交易平台提供免费、含 SLA 的引擎接入——极强的价格杀伤力。

「用好 API」是我们的隐形卖点：同样一套 API，会用和不会用差很多。我们把最佳实践直接做进了产品——比如监控用 hops=1「只看对手方地址本身是否触发高风险标签」，比盲目多跳快一个量级；再配自定义规则把误报压低。这份「知道怎么用对」本身就是价值。

客户类型核心场景切入话术

06现场 Demo 脚本 · 5 步走

照着演，10 分钟讲完全流程。演示前先准备好：一个已知高风险地址、一笔可疑交易哈希。

KYA 地址筛查——先给个「震撼弹」

粘一个已知制裁/黑客地址，让它自动识别链，点筛查。

话术：「你看，这个地址直接命中『严重』，右边是它跟制裁实体之间的完整资金路径——这就是我们给监管交代的证据。」

KYT 交易筛查——展示方向感

粘一笔交易哈希，选 in 查来源，再切 out 查去向。

话术：「同一笔交易，进和出用不同规则。系统直接告诉你该拦截还是放行，不用人肉判断。」

地址监控——证明「全量、不漏」

添加一个活跃地址，打开交易台账，切「只看有问题的」，展示时段统计。

话术：「它后续每一笔我们都自动检测了，这是台账；这个时段共 128 笔，其中 3 笔严重——一笔都没漏。」

TX 监控——讲「持续盯对手方」

从刚才的 KYT 结果，把对手方加入监控，说明 hops=1 只看它本身标签。

话术：「今天干净不代表明天，一旦这个对手方被打上制裁或冻结标签，你第一时间收到告警。」

设置——收尾讲「可控 + 安全」

展示三把 Key 的 Test 按钮、自定义 ruleset id，强调数据自托管。

话术：「规则你自己定，越贴业务越准；整套开源自部署，数据不出你的服务器。」

07异议处理 · 客户常问什么

点开看标准答案。核心原则：不虚，能证明。

和 Chainalysis / TRM 有什么区别？
我们自建制裁数据与标签库、覆盖 11 条链，规则可自定义；而且 AMLClaw 开源、可私有部署，数据不出客户服务器——Chainalysis 是黑盒 SaaS、数据要上云、价格高。再加上 Width 对大客户免费接入，性价比是碾压级的。
数据准不准？覆盖够不够？
自建制裁数据库覆盖 OFAC / UN / EU / UK 等名单，百万级标签地址，由专职情报团队持续校验，秒级检索、11 链近实时。演示时直接拿已知制裁地址命中给客户看，比嘴说管用。
支持哪些链？我们主要用 BSC / 别的链。
产品目前演示 ETH（USDT+USDC）和 Tron（USDT），地址/哈希自动识别链；底层引擎覆盖 11 条链，BSC 等可扩展。如果客户强需求某条链，记录下来我们评估排期。
要收费吗？多少钱？
AMLClaw 本身开源免费；底层 Width API 对钱包、托管、支付、交易平台等大客户提供免费、含 SLA 保障的接入。落地成本主要是部署，几乎没有软件许可费——这是我们最强的临门一脚。
部署复杂吗？我们技术团队不大。
无数据库、文件存储，docker compose up 一键起，只需一把 width.info API Key（Etherscan/TronGrid Key 可选，用于监控喂交易流）。设置页有 Test 按钮当场验 Key 通不通。
会不会误报太多，淹没我们的人？
三招压误报：① 用自定义 ruleset 只保留跟业务相关的风险类别和阈值；② 入金出金用不同方向规则；③ 持续监控用 hops=1 只看对手方本身标签，不做深度铺开。风险还按严重度排序，先看最该看的。
持续监控会不会又慢又费额度？
不会。监控用 hops=1（只查对手方地址本身的标签）、每轮只筛 [上次运行→现在] 的增量、任务串行排队尊重 API 并发上限。速度快、调用省，专为高频场景设计。
我们的数据安全吗？会上传到你们那吗？
自托管，数据留在客户自己服务器；无数据库，API Key 只存在本地、响应里还做脱敏。除了调用 Width/Etherscan/TronGrid 这几个必要 API，不外发任何数据。

08术语速查

客户抛术语时不卡壳。

术语一句话解释
KYAKnow Your Address，查一个地址的风险（自身命中 + 间接敞口）。
KYTKnow Your Transaction，查一笔交易的资金来源/去向是否涉险。
hop（跳）资金转手的层数。1 跳=直接对手方；5 跳=追溯 5 层上游。监控用 1 跳最快。
ruleset规则集。决定命中哪些风险类别、什么阈值算风险。可用默认或自定义。
in / out方向。收款=in（查钱从哪来），付款=out（查钱到哪去）。
Sanctions制裁。地址涉及 OFAC 等制裁名单——最高危信号。
Freeze冻结。地址被公开冻结行动标记。
风险等级low / medium / high / critical，由规则集判定，不是一个固定分数。
PEP政治公众人物，尽调中的高关注对象。
