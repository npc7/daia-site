一句话版本：一套链上情报与风控引擎，把脏钱挡在门外，每一笔都可解释、可追溯。

01DAIA 是什么 · 三层要讲清

客户最容易在「引擎 / API / 应用」这层绕晕，先把关系摆明白。

核心产品（我们卖的）

Width DAIA 引擎

链上情报与风控引擎：自建制裁数据、百万级标签、11 链近实时、5 跳资金追溯。这是我们真正的数据与能力资产。

交付方式

KYA / KYT API

把引擎能力开放成一套 REST API：KYA 查地址、KYT 查交易。客户拿一把 Key 就能接。在 width.info 申请。

开源样板 / 演示

AMLClaw 应用

DAIA 团队开源的参考应用，把 API 封装成开箱即用的界面。客户拿它看效果、做 POC、直接部署都行。

类比帮客户理解：DAIA 是「发动机」，KYA/KYT API 是「油管接口」，AMLClaw 是我们开源的一台样车——客户既能只接 API 自己造车，也能直接开走这台样车。我们卖的是发动机（引擎能力），AMLClaw 是让客户一眼看懂的展车。

02客户为什么需要它

卖的不是功能，是「不出事」。先戳痛点，再给方案。

客户的三大痛点

  • 监管压力：MAS、FATF Travel Rule、各地牌照都要求对加密资金做 AML/KYT，做不到就拿不到 / 保不住牌照。
  • 脏钱风险：一旦收了制裁地址、混币器、黑客赃款的钱，账户可能被冻结、被追责，声誉和资金双输。
  • 说不清：出事时监管问「你当时怎么判断这笔干净？」，客户拿不出证据链，等于裸奔。

DAIA 怎么对症

  • 痛点一 → 事前筛查：入金/出金前先查地址和交易，脏钱挡在门外。
  • 痛点二 → 持续监控：地址收钱后持续盯，脏钱流入立刻告警，不是查一次就完（AMLClaw 的两个监控模块）。
  • 痛点三 → 可解释证据：每次命中都返回触发的具体规则 + 资金路径，即拿即用的审计依据，支撑 MAS PSN02、FATF Travel Rule。

03DAIA 四大能力

引擎对外的四块核心能力——基于我们自己的数据、标签、规则。

KYA

地址筛查

对任意地址做 0–5 跳的自身命中与间接敞口筛查——制裁、恐怖融资、混币器、黑客、暗网等。重要性阈值可调，把误报压低。

KYT

交易筛查

区分入金 / 出金方向的实时交易筛查，按「本笔资金」向上溯源，实时拦截或升级处置。

Sanctions

制裁筛查

自建制裁数据库，覆盖 OFAC、UN、EU、UK 等名单——主体、个人、企业、地址，秒级检索。

Intelligence

链上情报标签库

持续更新的交易所、DeFi 协议、混币器、黑客与暗网实体标签，由专职情报团队校验。

04它如何工作 · 三步

给客户讲清落地路径：接一套 API，实时筛，拿到可解释结果。

接入 API

一套 REST API，三套内置规则集（KYA / KYT-IN / KYT-OUT），也支持自定义阈值与规则。

实时筛查

每个地址、每笔转账实时比对制裁、犯罪与混淆风险——按跳数分级的重要性控制，把误报压到最低。

可解释的结果

每次命中返回触发的具体规则清单 + 资金路径——即拿即用的审计依据，支撑 MAS PSN02、FATF Travel Rule 等合规场景。

05AMLClaw 参考应用 · 也是「怎么用好 API」的样板

AMLClaw 是 DAIA 团队开源（MIT、可私有部署）的参考应用，把 KYA/KYT 封装成四个开箱即用的工作流。它最大的价值：把「API 怎么用对」直接做进了产品。

工作流

KYA 地址筛查 + KYT 交易筛查

一键查一个地址或一笔交易哈希（自动识别 ETH / Tron），区分方向，带完整路径证据和可交互资金流向图。

工作流

地址监控 + TX 监控

地址监控盯一个地址后续每笔转账并自动 KYT；TX 监控盯某笔交易的对手方（from/to）标签变化，涉制裁/冻结立即告警。

「用好 API」是我们的隐形卖点。同一套 API，会用和不会用差一个量级。AMLClaw 把最佳实践沉淀了下来，这几条一定要讲给客户：

实践怎么做 / 为什么
hops = 1做持续监控时只用 1 跳——只看对手方（from/to）地址本身是否触发高风险标签（制裁/冻结）。一跳省去深度图遍历，快一个量级，正是高频监控需要的。
自定义 ruleset别用 ruleset_id 的宽泛默认值。指向客户自己的规则集，挑贴业务的类别和阈值 → 更精准、误报更少。
按需深筛多跳（3–5）留给一次性的入/出金筛查——那种真要追溯资金来源的场景。别把深跳塞进监控循环，深度只换延迟。
滚动窗口 · 串行每轮只筛 [上次运行→现在] 的增量，任务串行排队尊重 API 并发上限。速度快、调用省，每笔入台账证明全量覆盖。

08现场 Demo 脚本 · 5 步走

用 AMLClaw 演，10 分钟讲完全流程。演示前准备好：一个已知高风险地址、一笔可疑交易哈希。

KYA 地址筛查——先给个「震撼弹」

粘一个已知制裁/黑客地址，自动识别链，点筛查。

话术：「这个地址直接命中『严重』，右边是它跟制裁实体之间的完整资金路径——这就是我们给监管交代的证据。」

KYT 交易筛查——展示方向感

粘一笔交易哈希，选 in 查来源，再切 out 查去向。

话术：「同一笔交易，进和出用不同规则。系统直接告诉你该拦截还是放行，不用人肉判断。」

地址监控——证明「全量、不漏」

添加一个活跃地址，打开交易台账，切「只看有问题的」，展示时段统计。

话术：「它后续每一笔我们都自动检测了，这是台账；这个时段共 128 笔，其中 3 笔严重——一笔都没漏。」

TX 监控——讲「持续盯对手方」

从刚才的 KYT 结果，把对手方加入监控，说明 hops=1 只看它本身标签。

话术：「今天干净不代表明天，一旦这个对手方被打上制裁或冻结标签，你第一时间收到告警。」

设置——收尾讲「可控 + 安全」

展示三把 Key 的 Test 按钮、自定义 ruleset id，强调数据自托管。

话术：「规则你自己定，越贴业务越准；整套开源自部署，数据不出你的服务器。」

09异议处理 · 客户常问什么

点开看标准答案。核心原则：不虚，能证明。

和 Chainalysis / TRM 有什么区别？
我们自建制裁数据与标签库、覆盖 11 条链，规则可自定义；参考应用 AMLClaw 开源、可私有部署，数据不出客户服务器——Chainalysis 是黑盒 SaaS、数据要上云、价格高。再加上我们对大客户免费接入，性价比是碾压级的。
数据准不准？覆盖够不够？
自建制裁数据库覆盖 OFAC / UN / EU / UK 等名单，百万级标签地址，由专职情报团队持续校验，秒级检索、11 链近实时。演示时直接拿已知制裁地址命中给客户看，比嘴说管用。
支持哪些链？我们主要用 BSC / 别的链。
引擎侧覆盖 11 条链近实时；参考应用 AMLClaw 目前演示 ETH（USDT+USDC）和 Tron（USDT），地址/哈希自动识别链，BSC 等可扩展。客户强需求某条链，记录下来我们评估排期。
要收费吗？多少钱？
对钱包、托管、支付、交易平台等大客户，Width 提供免费、含 SLA 保障的引擎接入；参考应用 AMLClaw 开源免费。落地几乎没有软件许可费——这是我们最强的临门一脚。具体商务政策以公司口径为准。
接入 / 部署复杂吗？我们技术团队不大。
API 一套 REST 接口，三套内置规则集，拿 Key 即用。想快速看效果就直接部署开源的 AMLClaw：无数据库、docker compose up 一键起，设置页有 Test 按钮当场验 Key 通不通。
会不会误报太多，淹没我们的人？
三招压误报：① 用自定义 ruleset 只保留相关风险类别和阈值；② 入金出金用不同方向规则；③ 按跳数分级的重要性控制。持续监控还用 hops=1 只看对手方本身标签，风险按严重度排序，先看最该看的。
持续监控会不会又慢又费额度？
不会。监控用 hops=1（只查对手方地址本身标签）、每轮只筛 [上次运行→现在] 增量、任务串行排队尊重 API 并发上限。速度快、调用省，专为高频场景设计。
我们的数据安全吗？会上传到你们那吗？
用开源的 AMLClaw 自托管，数据留在客户自己服务器；无数据库，API Key 只存本地、响应里还脱敏。除了调用 DAIA/Etherscan/TronGrid 这几个必要 API，不外发任何数据。

10术语速查

客户抛术语时不卡壳。

术语一句话解释
DAIA我们的链上情报与风控引擎，KYA/KYT/制裁/标签能力都来自它。
KYAKnow Your Address，查一个地址的风险（自身命中 + 间接敞口）。
KYTKnow Your Transaction，查一笔交易的资金来源/去向是否涉险。
hop（跳）资金转手的层数。1 跳=直接对手方；5 跳=追溯 5 层上游。监控用 1 跳最快。
ruleset规则集。决定命中哪些风险类别、什么阈值算风险。可用默认或自定义。
in / out方向。收款=in（查钱从哪来），付款=out（查钱到哪去）。
Sanctions制裁。地址涉及 OFAC 等制裁名单——最高危信号。
Freeze冻结。地址被公开冻结行动标记。
风险等级low / medium / high / critical，由规则集判定，不是一个固定分数。
